# 遊戲開發總部

每次打開專案，先看這一頁。它告訴你：現在做哪一款、做到哪、下一步是什麼。

## 現在在做什麼

| 遊戲 | 角色 | 時間分配 | 目前階段 | 下一個里程碑 |
|---|---|---|---|---|
| [回聲病棟](echo-ward/README.md) | **主線** | 每週 4 天（約 80%） | M0 網頁原型 ✅ | M1：在 Godot 做出第一章灰盒 |
| [第七次葬禮](seventh-funeral/README.md) | 副線 | 每週 1 天（約 20%） | M0 網頁原型 v0.3 ✅ | F1：設計文件與美術風格定稿 |
| [肉繭修道院](_parked/cocoon-abbey/README.md) | 暫停 | 0 | 網頁原型 | 回聲病棟上架後再評估 |

> 想換主線？只要改上面這張表，並在兩款的 `roadmap.md` 註明日期和原因。不要兩款同時當主線。

### 為什麼回聲病棟先做

- **範圍最小**：只有一個核心機制（回聲），沒有戰鬥手感要調，美術可以藏在黑暗裡。
- **先跑完一次上架流程**：Steam 商店頁、願望清單、新品節、建置上傳、評論應對。第一次一定會踩坑，在小的遊戲上踩比較便宜。
- **第七次葬禮需要更多經驗**：戰鬥手感、Roguelike 平衡、像素美術量都比較大。做完回聲病棟，你會用同一套 Godot 技術把它做得更好。

## 五條規則（避免亂掉）

1. **一次只有一款主線。** 副線只做「不寫程式」的工作：劇本、民俗研究、像素美術、音樂、商店頁文案。主線卡住時，也不要跳去副線寫程式；卡住就寫進 devlog，換主線裡的另一件事做。
2. **新點子先丟收集箱。** 不管是哪一款的點子，一律先寫進 [`shared/ideas-inbox.md`](shared/ideas-inbox.md)，不直接做。每週日看一次，決定刪掉、留著，或排進某款的 `tasks.md`。
3. **範圍鎖定。** 每款的 `README.md` 都有「1.0 做什麼 / 不做什麼」。不在清單上的東西，1.0 就不做。
4. **里程碑有完成條件。** `roadmap.md` 裡每個階段都寫了「怎樣才算完成」。沒達成就不進下一階段，不准「差不多了」。
5. **每週寫三行 devlog。** 做了什麼、卡在哪、下週做什麼。半年後你會感謝自己。

## 每週節奏

| 時間 | 做什麼 |
|---|---|
| 週一（10 分鐘） | 打開主線的 `tasks.md`，從「下一步」拉 3～5 件到「這週」 |
| 週一～週四 | 主線：回聲病棟 |
| 週五 | 副線：第七次葬禮（只做非程式工作） |
| 週日（15 分鐘） | 兩款各寫一段 devlog；整理 ideas-inbox |

時間假設是每週約 20 小時。如果你能投入的時間不同，等比例調整 `roadmap.md` 的月份即可，順序不變。

## 資料夾地圖

```
games/
├── README.md                ← 你在這裡：總覽、規則、節奏
├── echo-ward/               ← 回聲病棟（主線）
│   ├── README.md            ← 一頁簡介 + 範圍鎖定
│   ├── GDD.md               ← 遊戲設計文件（機制、守衛、章節、劇情）
│   ├── roadmap.md           ← 里程碑與完成條件
│   ├── tasks.md             ← 待辦：這週 / 下一步 / 之後
│   ├── devlog.md            ← 開發日誌
│   └── prototype/           ← 可玩的網頁原型（瀏覽器直接開）
├── seventh-funeral/         ← 第七次葬禮（副線），結構同上
├── _parked/                 ← 暫停的專案，不刪，但不碰
│   └── cocoon-abbey/
└── shared/                  ← 兩款共用
    ├── ideas-inbox.md       ← 新點子收集箱
    ├── steam-checklist.md   ← Steam 上架流程清單
    └── tech-notes.md        ← 兩款共用的技術筆記
```

## Git 習慣

- commit 訊息開頭標遊戲代號：`[echo]`、`[funeral]`、`[shared]`。例如：`[echo] 盲眼修士會追蹤腳步聲`。
- 正式用 Godot 開工時，**每款遊戲各開一個獨立的 repo**。遊戲素材（貼圖、音檔、模型）很大，跟這個數據分析專案混在一起會很難管。這個 `games/` 資料夾可以繼續當「規劃總部」用。
